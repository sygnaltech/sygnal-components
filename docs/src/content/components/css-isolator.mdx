# CSS Isolator

![CSS Isolator component in Webflow Designer](/components/css-isolator.png)

Webflow's Native Component and Code Component styling doesn't directly support styling individual component instances. CSS Isolator fills that gap — wrap any group of components or elements in a CSS Isolator and provide CSS or CSS variable overrides that apply only to that specific instance.

**Group:** Style

## Features

- Provide custom CSS that applies only to the slotted content — works with Native Components, Code Components, and Shared Libraries
- Provide CSS variable overrides that apply only to the slotted content — works with Code Components, Native Components, and Shared Libraries
- Each isolator gets a unique auto-generated ID so styles never leak to other instances

## Properties

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `cssVars` | Text | — | CSS custom property overrides applied to the scoped container (e.g., `--color-brand: #ff6600;`). |
| `css` | Text | — | Full CSS rules to scope to this container. Selectors are automatically prefixed with the container's unique ID. |
| `slot` | Slot | — | Components and elements that should be affected by the isolated CSS rules. |

## How It Works

When the component mounts, it generates a unique ID (UUID v4) and creates a wrapping `<div id="{uuid}">`. Any CSS you provide in the `css` property is transformed so that every selector is prefixed with `#{uuid}`:

```css
/* Your input */
.button { color: red; }
h2 { font-size: 2rem; }

/* Applied to the page */
#a1b2c3d4 .button { color: red; }
#a1b2c3d4 h2 { font-size: 2rem; }
```

CSS custom properties from `cssVars` are applied directly to the container element, making them available to all descendants via the CSS cascade.

## CSS Variables

Use the `cssVars` property to override design tokens or CSS custom properties for everything inside the isolator:

```css
--color-brand: #ff6600;
--font-size-heading: 2.5rem;
--spacing-section: 4rem;
```

These variables cascade normally within the scoped container. Components that consume these variables will pick up the overridden values.

## Scoped CSS Rules

Use the `css` property for full CSS rules. Selectors are prefixed automatically — you write standard CSS:

```css
.card {
  border-radius: 12px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
}

h2 {
  font-weight: 700;
  color: var(--color-brand);
}
```

## Use Cases

### Per-section theme overrides

Apply different brand colors to two sections of the same page that use the same components:

```css
/* Section 1 CSS Isolator cssVars */
--color-brand: #0055ff;
--color-accent: #00ccff;

/* Section 2 CSS Isolator cssVars */
--color-brand: #ff3300;
--color-accent: #ffaa00;
```

### One-off component styling

Style a specific component instance without affecting global styles or creating new Webflow classes:

```css
.my-component { padding: 2rem; background: #f5f5f5; }
```

## Limitations

- In some cases, styling may not render correctly at design-time due to differences in the Webflow design canvas. Most styles will be visible in the Designer, but publish to staging or use Preview mode to verify complex cases.
- The selector prefixer uses a regex-based approach, not a full CSS parser. Complex selectors involving pseudo-elements (`::before`, `::after`) or at-rules (`@media`, `@keyframes`) may not be prefixed correctly.

## HTML Encoding

Both `cssVars` and `css` values are HTML-decoded before being applied, so HTML entities like `&gt;` and `&amp;` entered through the Webflow Designer text fields are correctly handled.
